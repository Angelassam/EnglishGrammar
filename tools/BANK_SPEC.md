# 문제 은행 작성 규격 (app/data/bank/<단원id>.json)

## 파일 형태

```json
{
 "unit": "1-06",            // app/data/units.json의 id. Part 2 단원은 "1-06-P2"
 "grade": 1,                // 1 또는 2 (units.json과 같아야 함)
 "title": "조동사 must·should·have to",   // units.json의 title 그대로
 "source": "06_조동사_must_should_have_to.md — Part 1. 중1 기초",   // 근거 문서 (🔁 문서는 Part 표시)
 "questions": [ ... ]
}
```

## 문제 5유형

모든 문제 공통: `id`(= "<unit>-<유형약자><번호>", 예 1-06-c01, 1-06-e01, 1-06-b01, 1-06-f01, 1-06-a01), `type`, `e`(해설), `ref`(근거가 된 문서 안의 소제목).

### 1. choice — 객관식 (알맞은 말 고르기)
```json
{"id":"1-06-c01","type":"choice",
 "q":"우리말과 같은 뜻이 되도록 빈칸에 알맞은 말을 고르세요.<br>너는 복도에서 뛰면 안 된다.<br>You ____ run in the hallway.",
 "o":["must not","must","should","have to","had to"], "a":0,
 "e":"'~하면 안 된다'는 금지의 뜻이라 must not을 써요. must, have to는 '~해야 한다'예요.",
 "ref":"1. must — 의무"}
```
- `o`: 보기 **정확히 5개**, 서로 다른 것. 정답은 **딱 1개**여야 하고 나머지 4개는 분명히 틀려야 함.
- `a`: 정답 번호(0부터). 앱이 보기 순서를 섞으므로 항상 0에 정답을 두어도 됨.
- `q` 안의 줄바꿈은 `<br>`, 강조는 `<b>`, 밑줄은 `<u>`만 사용. 빈칸은 `____`(밑줄 4개).
- 다양한 형태를 섞기: 우리말 뜻 주고 빈칸 / 영어만 빈칸(+`ko`로 우리말) / 대화 빈칸 / 밑줄 친 부분과 바꿔 쓸 수 있는 것 / 어법상 옳은 문장 / 문장의 뜻·용법 고르기.
- 선택: `"ko"`(문제 문장의 우리말 뜻, 문제 바로 아래 괄호로 표시됨).

### 2. error — 객관식 (어법상 틀린 것 고르기)
```json
{"id":"1-06-e01","type":"error","q":"다음 중 어법상 틀린 문장을 고르세요.",
 "o":["She must finishes it.","You must wear a seat belt.","He has to take the bus.","You should exercise regularly.","I had to wait for an hour."],
 "a":0,"e":"조동사 뒤는 동사원형이라 finishes가 아니라 finish를 써야 해요. → She must finish it.","ref":"주의! 조동사 뒤는 동사원형"}
```
- 틀린 문장 1개 + **완전히 맞는 문장 4개**. 해설에 고친 문장을 적기.

### 3. blank — 빈칸 채우기 (학생이 직접 씀)
```json
{"id":"1-06-b01","type":"blank",
 "q":"괄호 안의 말을 알맞은 형태로 바꿔 빈칸에 쓰세요.<br>He ____ clean his room. (have to)",
 "ko":"그는 자기 방을 청소해야 한다.", "ans":["has to"],
 "e":"주어가 He라서 have to가 has to로 바뀌어요.","ref":"2. have to — 주어에 따른 형태"}
```
- `ans`: 정답으로 인정할 답 **모두** (축약형 don't / do not 같은 변형 포함). 채점은 대소문자·구두점·띄어쓰기 무시.
- 답이 하나로 정해지도록 단어 수("(두 단어)")나 괄호 힌트를 꼭 주기.

### 4. fix — 틀린 부분 고쳐 쓰기
```json
{"id":"1-06-f01","type":"fix","q":"She must finishes her homework.","wrong":"finishes",
 "ko":"그녀는 숙제를 끝내야 한다.","ans":["finish"],
 "e":"조동사 must 뒤에는 동사원형이 와요. finishes → finish","ref":"주의! 조동사 뒤는 동사원형"}
```
- `q`는 틀린 문장 전체, `wrong`은 그 안에서 밑줄 칠 틀린 부분(문장 안에 **그대로** 들어 있어야 함, 한 번만 등장).
- `ans`: 고친 부분(들). 학생이 문장 전체를 고쳐 써도 앱이 인정함.
- `ko` 필수(우리말 뜻이 있어야 고칠 방향이 하나로 정해짐).

### 5. arrange — 배열·영작
```json
{"id":"1-06-a01","type":"arrange","ko":"너는 안전벨트를 매야 한다.",
 "words":["wear","must","You","a seat belt"],"ans":["You must wear a seat belt."],
 "e":"주어 + must + 동사원형 순서로 써요.","ref":"1. must — 의무"}
```
- 기본: `words`를 **그대로** 배열하면 `ans[0]`이 됨 (단어·덩어리 수와 내용이 정확히 일치해야 함, 점검 도구가 확인). 덩어리는 섞어서 적기.
- 형태를 바꾸거나 단어를 더해야 하는 영작은 `"cond":"주어진 말을 이용하고, 필요하면 단어를 더하거나 형태를 바꾸세요."`를 넣고 `words`에 원형을 둠.
- 어순이 두 가지 이상 가능하면 모두 `ans`에 넣기.

## 반드시 지킬 것

1. **문법 설명·정답 근거는 해당 문법 문서 안의 내용만** 사용. 문서에 없는 규칙을 지어내지 않기. 문서의 예문을 그대로 쓰거나 살짝 바꿔 쓰는 것을 우선하고, 새 문장은 중학 교과서 수준 어휘로.
2. **영어 문장은 영어예문_검수_규칙.md의 체크리스트**로 하나씩 확인 (수일치, 시제, 동사 형태, 관사·전치사, 철자, 자연스러움, 우리말 1:1 대응).
3. **중1 단원(🔁 문서의 Part 1)에는 Part 2 내용이 절대 들어가면 안 됨.** Part 2 단원(-P2)은 Part 2 내용 중심으로 하되, Part 1 기초를 섞어도 됨.
4. 해설은 짧고 친절한 **한국어 존댓말(~해요 체)**, 1~2문장. 정답 이유와 대표 오답이 왜 틀렸는지.
5. 정답이 **하나로 분명하게** 정해져야 함. 두 보기가 다 될 수 있는 문제, 다른 답도 가능한데 `ans`에 빠진 서술형은 금지.
6. 한 단원 문제 수: **30개 이상** — choice 10 이상, error 4 이상, blank 5 이상, fix 5 이상, arrange 5 이상. 문장과 어휘는 서로 겹치지 않게.
7. 작성 후 `node tools/check_bank.js`를 돌려 "모두 통과"가 나와야 함.
